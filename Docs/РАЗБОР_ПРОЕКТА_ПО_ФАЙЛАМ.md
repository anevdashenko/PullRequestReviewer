# Разбор проекта по файлам (для разработчика Unity без опыта в вебе)

Документ описывает **только код и конфигурацию репозитория** — без разбора содержимого `node_modules`. Цель: связать знакомые идеи из Unity/игр с тем, как устроены **Node.js**, **HTTP API**, **браузерный фронт** и **инфраструктура** в этом проекте.

Связанные материалы: [WEBHOOK.md](WEBHOOK.md) (запуск и GitHub).

---

## 1. Коротко: аналогии с Unity

| Unity / игра | В этом веб-проекте |
|----------------|---------------------|
| **Игра крутится в кадрах**, реагирует на ввод | **Сервер «спит»»**, просыпается на **входящий HTTP-запрос** (событие извне), обрабатывает и отвечает |
| **Сцена** с UI и логикой | **Маршрут** (URL) + обработчик: что показать / что вернуть в JSON |
| **PlayerPrefs** | **localStorage** в браузере (строка ключа админа) |
| **Coroutine** `yield return` + async в C# | **async/await** в TypeScript: «подожди сеть/БД, не блокируй поток» |
| **Addressables / загрузка с сервера** | Браузерный **`fetch(url)`** — GET/POST как «RPC без Unity» |
| **ScriptableObject / таблица данных** | **Строки в PostgreSQL**, описанные в `schema.prisma` |
| **Очередь заданий в своём Job System** | **BullMQ + Redis**: API кладёт задачу, **отдельный процесс worker** забирает |
| **Build Player** | **`npm run build`** → папка `dist/` с JS, который запускает `node` |
| **Docker** | «Коробка» с нужными службами (БД, Redis, api, worker), чтобы окружение было воспроизводимым |

Важно: веб-сервер чаще **stateless** по запросу — между двумя запросами от одного клиента он не обязан держать ваш объект в памяти; состояние живёт в **БД**, **кэше**, **куках** или на **клиенте**. Здесь состояние настроек и журналов — в **Postgres**.

## 2. Стек и зачем каждая часть

| Технология | Роль в проекте |
|------------|----------------|
| **TypeScript** | JavaScript + типы на этапе разработки; в рантайме выполняется скомпилированный **JS** (`dist/`). |
| **Node.js** | Среда выполнения сервера и воркера (как CLR для .NET, но для JS). |
| **Fastify** | Фреймворк HTTP: маршруты, middleware/hooks, JSON, коды ответов. Альтернативы: Express, Hono. |
| **Prisma** | ORM: модели в `schema.prisma` → типобезопасные запросы к Postgres из кода + миграции. |
| **PostgreSQL** | Реляционная БД: репозитории, правила, логи ревью. |
| **Redis + BullMQ** | Очередь фоновых задач между `index.ts` и `worker.ts`. |
| **@octokit/rest** | Официальный клиент GitHub REST API: дифф PR, создание review. |
| **openai** | SDK для вызова Chat Completions у OpenAI. |
| **Vite** | Сборщик и дев-сервер фронтенда; HMR (быстрая перезагрузка при правках). |
| **React** | UI из компонентов + состояние (`useState`, `useEffect`). |
| **react-router-dom** | Маршрутизация в SPA: `/`, `/logs`, `/repos/:id/rules` без перезагрузки страницы. |
| **Docker Compose** | Поднять Postgres, Redis, api и worker одной командой. |

В `backend/package.json` поле `"type": "module"` означает **ESM-модули**: в исходниках импорты пишутся с суффиксом **`.js`**, даже из `.ts` файлов — так требует режим **NodeNext** у TypeScript (путь после компиляции).

## 4. Backend: точка входа и HTTP

### [backend/src/index.ts](../backend/src/index.ts)

**Задача:** поднять HTTP-сервер и зарегистрировать поведение на путях.

- **`Fastify({ logger: true })`** — создаёт приложение с логированием запросов.
- **`app.register(cors, …)`** — CORS: браузеру с другого origin (например `localhost:3001`) разрешено читать ответы API и слать заголовок `X-Admin-Key`.
- **`addContentTypeParser('application/json', { parseAs: 'buffer' }, …)`** — нестандартный разбор тела запроса: тело приходит как **Buffer** (сырые байты), чтобы для пути **`/webhooks/github`** сохранить **`rawBody`** в объекте запроса. Это нужно для **подписи GitHub**: HMAC считается по **точным байтам** тела, а не по уже распарсенному JSON (пробелы могут отличаться).
- **`app.get('/api/health', …)`** — публичный healthcheck (без админ-ключа).
- **`registerAuthedApi` с префиксом `/api`** — все маршруты из `api.ts` становятся `/api/repos`, и т.д.; внутри плагина висит **`preHandler`** `requireAdmin`.
- **`registerWebhookRoutes`** — регистрирует **`POST /webhooks/github`** без префикса (полный путь с корня).
- **`app.listen({ port, host })`** — слушать интерфейс (`0.0.0.0` в Docker = все интерфейсы контейнера).

**Аналогия:** как `void Start()` в `MonoBehaviour`, только вместо `Update()` у вас **события**: пришёл запрос → вызвалась зарегистрированная функция.

---

### [backend/src/plugins/admin-auth.ts](../backend/src/plugins/admin-auth.ts)

**Задача:** защитить админские API.

- **`requireAdmin`** — читает `process.env.ADMIN_API_KEY`, сравнивает с заголовком **`X-Admin-Key`**. При несовпадении — **401** / **503**, если ключ в окружении не задан.
- **`registerAuthedApi`** — **`app.addHook('preHandler', requireAdmin)`**: перед **каждым** обработчиком маршрутов внутри этого плагина вызывается проверка. Это похоже на **pipeline** или общий «guard» перед контроллером.

**Важно:** `/api/health` зарегистрирован **вне** этого плагина в `index.ts`, поэтому health остаётся открытым.

---

### [backend/src/routes/api.ts](../backend/src/routes/api.ts)

**Задача:** REST-поверхность для админки (все пути ниже — **относительно префикса** `/api`, то есть фактически `/api/repos` и т.д.).

| Метод и путь | Что делает |
|--------------|------------|
| `GET /repos` | Список репозиториев; `include: { rules }` — Prisma сразу подтягивает связанные правила; в ответе токены **не** отдаются (маппинг вручную). |
| `POST /repos` | Создаёт `Repository` + вложенное создание `ReviewRule` с дефолтным промптом и моделью. Код **201** при создании. |
| `GET /repos/:id` | Одна запись + правила; **404** если нет. |
| `DELETE /repos/:id` | Удаление; каскадно удалит правила и логи (см. `onDelete: Cascade` в схеме). **204** без тела. |
| `PUT /repos/:id/rules` | **`upsert`** по `repoId`: если правил не было — создать, иначе обновить только переданные поля. `excludeGlobs` кладётся как JSON в Postgres (`Prisma.InputJsonValue`). |
| `GET /repos/:id/logs` | Логи одного репо с лимитом из query. |
| `GET /logs` | Общий список логов; опциональный фильтр `?repoId=`. |

**Типы Fastify** вида `app.post<{ Body: … }>` — это **generics**: TypeScript знает форму `req.body` внутри обработчика.

**`reply.code(400).send({ error })`** — установить HTTP-статус и JSON-тело ответа.

---

### [backend/src/routes/webhooks.ts](../backend/src/routes/webhooks.ts)

**Задача:** принять событие от GitHub быстро и безопасно.

1. Берёт **`rawBody`** с запроса (должен быть заполнен парсером из `index.ts`).
2. Читает заголовок **`X-Hub-Signature-256`**.
3. Из **`req.body`** (уже объект) вытаскивает `owner` и `name` репозитория (несколько вариантов полей JSON — GitHub шлёт разные формы `repository`).
4. **`prisma.repository.findUnique({ where: { provider_owner_name: { … } } })`** — составной уникальный ключ из Prisma-схемы.
5. **`verifyGithubSignature`** — если подпись не сошлась → **401**.
6. Фильтр **`X-GitHub-Event`** = `pull_request` и `action` ∈ `opened` | `synchronize` | `reopened`; иначе **202** с `{ ignored: true }` (не ошибка, просто не наша работа).
7. Создаёт **`ReviewLog`** со статусом **`queued`**, вызывает **`enqueueReview`**, отвечает **202** `{ accepted, reviewLogId }`.

**Зачем 202, а не 200:** по смыслу «принято к обработке», тело тяжёлой работы — в воркере.

---

### [backend/src/db.ts](../backend/src/db.ts)

Экспорт **`PrismaClient`** в одном экземпляре. Паттерн «singleton», чтобы не плодить соединения к БД на каждый импорт.

---

### [backend/src/queue.ts](../backend/src/queue.ts)

- **`redisConnection`** — объект `{ host, port, maxRetriesPerRequest: null }` из `REDIS_URL` (BullMQ так тоже умеет).
- **`reviewQueue`** — очередь с именем `pr-review`.
- **`enqueueReview`** — `reviewQueue.add('review', { reviewLogId }, { attempts, backoff, removeOnComplete … })` — политика повторов при падении джобы.

**Аналогия:** `ConcurrentQueue` + фоновый поток, только consumer в **другом процессе** (`worker.ts`).

---

### [backend/src/worker.ts](../backend/src/worker.ts)

**Задача:** второй процесс Node, который **подписан** на ту же очередь.

- **`processReview(reviewLogId)`** — загрузка лога с `repository` и `rules`, статус → **`running`**, создание **`Octokit({ auth: token })`**, сбор диффа, вызов **`runLlmReview`**, **`submitGithubReview`**, финальный статус **`done`** + `rawAiOutput` + `finishedAt`.
- **`new Worker(PR_REVIEW_QUEUE, async (job) => { … }, { connection })`** — BullMQ вызывает колбэк для каждой джобы.
- **`worker.on('failed', …)`** — если джоба упала после исчерпания попыток, пишем в БД **`failed`** и обрезанный `errorMessage`.

**Параллель с Unity:** отдельный «сервис» без UI, только логика фона; как если бы вы вынесли тяжёлый пайплайн из главного потока в `Task.Run`, но здесь это **отдельный контейнер/процесс** в Docker.

---

### [backend/src/lib/webhook-signature.ts](../backend/src/lib/webhook-signature.ts)

**`verifyGithubSignature`:** HMAC-SHA256 от **сырого тела** с секретом репозитория, сравнение с заголовком в **constant time** (`timingSafeEqual`), чтобы усложнить timing-атаки.

---

### [backend/src/lib/pr-diff.ts](../backend/src/lib/pr-diff.ts)

**`buildPrDiffText`:**

- `octokit.pulls.get` — метаданные PR, нужен **`headSha`** (коммит «головы» PR) для создания review.
- `octokit.paginate(octokit.pulls.listFiles, …)` — все файлы PR с полем **`patch`** (текстовый unified diff по файлу).
- **`minimatch`** — проверка пути файла против списка glob из настроек; совпал — файл пропускается.
- Ограничение **`MAX_CHARS`** — если дифф огромный, обрезка с пометкой в тексте (чтобы не упереться в лимиты модели).

---

### [backend/src/lib/llm.ts](../backend/src/lib/llm.ts)

**`runLlmReview`:**

- Собирает сообщения **`system`** (ваш промпт + жёсткая инструкция формата JSON) и **`user`** (текст с диффом).
- **`response_format: { type: 'json_object' }`** — просим модель вернуть валидный JSON объект.
- Парсинг **`JSON.parse`**, защитная нормализация полей (`typeof` проверки), фильтрация пустых finding'ов.
- Экспорт типов **`AiReviewResult`**, **`AiFinding`** — используются в `review-submit.ts`.

---

### [backend/src/lib/review-submit.ts](../backend/src/lib/review-submit.ts)

**`submitGithubReview`:**

- Преобразует findings с **`line`** в массив **inline** комментариев для GitHub API (`side: 'RIGHT'` — привязка к правой стороне диффа, «новый» файл).
- Тело review собирает из **summary** и findings **без** строки (как маркированный список в markdown).
- **`octokit.pulls.createReview`** — сначала с inline; при ошибке — **fallback** только с `body` (часто из-за неверных номеров строк от модели).

## 5. Prisma и база данных

### [backend/prisma/schema.prisma](../backend/prisma/schema.prisma)

- **`model Repository`** — одна строка на подключённый репозиторий; **`@@unique([provider, owner, name])`** не даёт дублировать одну и ту же тройку.
- **`model ReviewRule`** — один-к-одному с репозиторием (`repoId @unique`); **`excludeGlobs Json`** — JSON-массив строк в Postgres.
- **`model ReviewLog`** — журнал прогонов; **`@@index([repoId, createdAt])`** ускоряет выборку последних логов по репо.

### [backend/prisma/migrations/…/migration.sql](../backend/prisma/migrations/)

SQL, который Prisma применяет к пустой базе. **`prisma migrate deploy`** в Docker применяет накопленные миграции на старте контейнера.

## 6. Frontend: SPA и вызов API

### [frontend/index.html](../frontend/index.html)

Минимальная HTML-оболочка: один **`div id="root"`**, куда React «монтирует» приложение. Скрипт `main.tsx` подключается как **module** (ESM в браузере).

### [frontend/vite.config.ts](../frontend/vite.config.ts)

- **`@vitejs/plugin-react`** — JSX/TSX, Fast Refresh.
- **`server.proxy`** — в режиме разработки запросы с браузера на **`/api`** и **`/webhooks`** проксируются на API (`PORT` из корневого `.env`, по умолчанию `http://127.0.0.1:3000`). Порт Vite — `FRONTEND_DEV_PORT` (по умолчанию 3001).

### [frontend/src/main.tsx](../frontend/src/main.tsx)

- **`createRoot(document.getElementById('root')!)`** — React 18+ API входа (как точка входа сцены).
- **`BrowserRouter`** — роутер, читающий **`window.location`**.
- **`StrictMode`** — в dev двойные вызовы эффектов для отлова побочных эффектов (может путать при отладке сети — это норма React).

### [frontend/src/App.tsx](../frontend/src/App.tsx)

**`Routes` / `Route`:** декларативная таблица URL → компонент.

- Вложенность: **`Layout`** оборачивает дочерние маршруты; **`Outlet`** внутри `Layout` — место, куда подставляется дочерний экран (как вложенная «подсцена» только для контента).

### [frontend/src/Layout.tsx](../frontend/src/Layout.tsx)

- **`NavLink`** — ссылки с активным стилем.
- Локальное состояние **`useState`** для поля ключа; **`setAdminKey`** пишет в **`localStorage`**.

### [frontend/src/api.ts](../frontend/src/api.ts)

- **`fetch`** — стандартный браузерный HTTP-клиент (Promise-based).
- Собирает заголовки: **`Content-Type: application/json`** если есть body; **`X-Admin-Key`** если ключ сохранён.
- При **`!res.ok`** пытается вытащить `{ error }` из JSON для человекочитаемого сообщения.
- **`204`** — успех без тела (типично для DELETE).

### Страницы в [frontend/src/pages/](../frontend/src/pages/)

- **`ReposPage`** — `useEffect` на монтирование вызывает **`load()`** (паттерн «при открытии экрана запросить данные»). Форма добавления репо — **`POST /api/repos`**.
- **`RulesPage`** — **`useParams`** достаёт `:id` из URL; **`PUT /api/repos/:id/rules`**.
- **`LogsPage`** — в зависимости от наличия **`repoId`** в пути вызывает либо **`/api/repos/:id/logs`**, либо **`/api/logs`**.

**Хуки React кратко:**

- **`useState`** — локальное состояние компонента (как поля + setter, только ререндер при изменении).
- **`useEffect(fn, [deps])`** — «после отрисовки выполни `fn`»; пустой массив зависимостей = один раз при монтировании (аналог `Start` / однократной подписки).

## 7. Docker и сборка

### [docker-compose.yml](../docker-compose.yml)

Описывает сервисы: **postgres**, **redis**, **api**, **worker**. Переменные из `.env` подставляются в `api` (в т.ч. `ADMIN_API_KEY`, `OPENAI_API_KEY`). Оба Node-сервиса перед стартом выполняют **`prisma migrate deploy`**.

### [backend/Dockerfile](../backend/Dockerfile)

Многостадийная сборка: **deps** (npm install + prisma в образе), **build** (generate + `tsc` + prune devDeps), **runner** (только прод-зависимости и `dist/`). Уменьшает размер финального образа.

### [backend/package.json](../backend/package.json)

- **`dev` / `worker`** — **`tsx watch`** запускает TypeScript напрямую в dev без предварительного `tsc` (удобно при разработке).
- **`build`** — **`tsc`** компиляция в **`dist/`**.
- **`postinstall`: `prisma generate`** — после `npm install` генерируется клиент Prisma под вашу схему.

## 8. Один сквозной запрос (закрепление)

1. Браузер: **`GET /api/repos`** с заголовком **`X-Admin-Key`** → прокси Vite → Fastify → **`requireAdmin`** → **`registerApiRoutes`** → Prisma → JSON в ответе.
2. GitHub: **`POST /webhooks/github`** с телом и подписью → парсер сохраняет **`rawBody`** → **`webhooks.ts`** → очередь → **worker** → Octokit + OpenAI + Octokit `createReview` → обновление **`ReviewLog`**.

## 9. Что почитать дальше (по направлениям)

- **HTTP:** методы, статус-коды, заголовки, JSON — общая база для любого бэкенда.
- **REST:** ресурсное именование путей (`/repos`, `/repos/:id`) и идемпотентность `GET`/`PUT`/`DELETE`.
- **React:** официальная документация по хукам и по **React Router** (у вас v7).
- **Node:** модель ESM, `process.env`, асинхронный I/O без блокировки потока (в отличие от синхронного файлового I/O в игровом кадре — здесь всё завязано на колбэки/Promise).
- **Prisma:** `findMany`, `create`, `upsert`, `include`, составные `where`.

Если будете расширять проект, логичные следующие шаги: вынести секреты из БД в vault, добавить аутентификацию пользователей вместо одного ключа, покрыть критичные пути тестами (например, Vitest на фронте, node:test или Vitest на бэке).
